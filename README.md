### 🛒 NexaShop — Multi-Role E-Commerce Backend

</div>

> **Stack:** `Java` `Spring Boot` `Spring Security` `MySQL` `Redis` `JWT`

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     ROLE-BASED ACCESS CONTROL                           │
│                                                                         │
│   👑 ADMIN          🏪 SELLER           🛍️ CUSTOMER                    │
│   ─────────         ──────────          ────────────                    │
│   User mgmt         Product CRUD        Browse & buy                    │
│   Platform ops      Order mgmt          Cart & checkout                 │
│   Full access       Own store only      Own orders only                 │
│                                                                         │
│   Spring Security · hasAuthority() · Zero role bleed guaranteed        │
└─────────────────────────────────────────────────────────────────────────┘
                              │
                    ┌─────────▼──────────┐
                    │  Auth Flow         │
                    │  ┌──────────────┐  │
                    │  │ Access Token │  │  Short-lived JWT
                    │  └──────┬───────┘  │
                    │         │ expires  │
                    │  ┌──────▼───────┐  │
                    │  │ Redis OTP    │  │  TTL-based expiry
                    │  │ Refresh flow │  │  Replay attacks: ✗
                    │  └──────────────┘  │
                    └────────────────────┘
```

| Feature | Detail |
|---|---|
| 🔐 Dual-token JWT | Access + refresh tokens with Redis OTP; TTL kills replay attacks |
| 🏦 Transactional checkout | Atomic stock validation — no overselling, no corrupt order state |
| ⚡ Async emails | Spring `@Async` — non-blocking, checkout throughput stays high |
| 🔒 Granular RBAC | `hasAuthority()` per endpoint — Admin ≠ Seller ≠ Customer, always |
